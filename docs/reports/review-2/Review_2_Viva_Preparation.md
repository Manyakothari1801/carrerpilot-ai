# Intelligent Career Guidance and Resume Optimization Platform Using AI — Review 2 Viva Preparation

1. **Why this project?** Career preparation is fragmented across resume, job-matching, practice, and scheduling tools; Career Guidance AI connects these stages for students.
2. **What is the research gap?** Existing studies often optimize one task. The project integrates explainable resume analysis, job-specific gaps, assessments, scheduling, and feedback.
3. **Where is AI used?** Gemini provides bounded qualitative resume feedback and optional assessment-question generation; deterministic algorithms handle core scoring and grading.
4. **Why Gemini?** It supports structured generation and is accessed behind a provider boundary with retry, discovery-based fallback, validation, and graceful degradation.
5. **Is the ATS score generated by Gemini?** No. It is deterministic and remains unchanged when Gemini fails.
6. **What does ATS-oriented mean here?** It is an explainable project score based on sections, keywords, action verbs, quantification, and readability—not a commercial ATS guarantee.
7. **How does job matching work?** It combines skill coverage, TF-IDF/cosine keyword similarity, optional semantic similarity, experience, and education.
8. **What is TF-IDF?** It weights terms by their importance in a document relative to common terms, enabling meaningful text-vector comparison.
9. **What happens when semantic similarity is unavailable?** The UI shows unavailable, and the overall score redistributes weight across available components.
10. **How are skill gaps detected?** Skills are normalized and classified by JD section context as REQUIRED, PREFERRED, or OPTIONAL; stronger importance wins during merging.
11. **Why do required skills rank higher?** Missing mandatory competencies have greater role impact than preferred or incidental mentions.
12. **How are questions randomized?** A new attempt selects exactly ten non-duplicate questions from the relevant stored bank.
13. **Why persist question snapshots?** Refresh returns the same questions and order, and historical attempts remain stable if the bank changes.
14. **How is answer leakage prevented?** Pre-submission DTOs omit correctness and explanations; these are revealed only after grading.
15. **Why server-side grading?** It prevents client manipulation and gives one authoritative deterministic result.
16. **How is expiry enforced?** The server compares current time with persisted attempt timing; the browser timer is informational.
17. **Are submitted attempts editable?** No. Submission is immutable and duplicate submission is rejected.
18. **How does scheduling work?** A student selects an assessment and future start time; the server derives the end from assessment duration.
19. **Why student-owned scheduling?** The current product supports self-directed preparation rather than administrator assignment.
20. **What is legacy V11 scheduling?** V11 introduced admin/candidate structures; V12 adds student ownership and audit fields while preserving legacy data.
21. **How are duplicate starts prevented?** The schedule is locked, linked to one attempt, and repeated starts return that linked attempt.
22. **How is ownership enforced?** Repository queries and services scope records to the authenticated user; cross-user requests return not found/denied.
23. **What is Flyway?** It applies ordered, versioned SQL migrations and validates database history. The project is at V12.
24. **Why PostgreSQL?** It provides relational constraints, transactions, indexing, and a production-oriented persistence model.
25. **Why Spring Boot?** It provides secure REST, validation, JPA, migrations, observability, and modular service organization.
26. **Why React and TypeScript?** React supports reusable UI state; TypeScript catches interface mismatches; Vite gives a fast build workflow.
27. **How is JWT used?** Signed access tokens identify users and roles; a filter establishes Spring Security authentication.
28. **How are passwords protected?** BCrypt hashes are stored; plaintext passwords are never persisted.
29. **How are secrets protected?** Database, JWT, and Gemini values come from environment variables and examples contain placeholders only.
30. **What happens when Gemini is overloaded?** Transient 429/503/network errors receive bounded retries; live model discovery may select another Flash model; otherwise analysis remains PARTIAL with deterministic findings.
31. **What is completed for Review 2?** Core security, profile, resume, analysis, matching, assessments, placement mocks, results, and student scheduling are substantially implemented.
32. **What remains?** Personalized recommendations, notifications, proctoring, combined readiness analytics, deployment, and final polish.
33. **Why call it AI-based if deterministic methods are used?** It deliberately combines generative AI for language feedback with transparent algorithms for reproducible decisions.
34. **What verification evidence exists?** The latest backend run passed 62 tests with zero failures; packaging passed, frontend builds have passed, and Flyway validates V12.
35. **What is the completion estimate?** Approximately 72%, based on implemented modules versus planned final scope, not an artificial feature count.
